
# Use Cases

## 1. Перечень вариантов использования

| ID | Вариант использования | Актор 
|---|---|---|
| UC-1 | Регистрация клиента | Администратор

| UC-3 | Создание заказа | Администратор 
| UC-4 | Назначение мастера | Администратор 
| UC-5 | Проведение диагностики | Мастер 
| UC-6 | Выполнение ремонта | Мастер

## 2. Описание

### UC-1. Регистрация клиента

**Актор:** Администратор

**Предусловие:** администратор авторизован в системе.

**Основной сценарий:**
1. Администратор открывает раздел клиентов.
2. Выбирает создание нового клиента.
3. Вводит ФИО и контактные данные.
4. Система проверяет введенные данные.
5. Система сохраняет информацию и присваивает клиенту ID.

**Альтернативный сценарий:** если обязательные данные не заполнены или имеют некорректный формат, система отображает ошибку.

### UC-2. Добавление оборудования

**Актор:** Администратор

**Предусловие:** клиент зарегистрирован в системе.

**Основной сценарий:**
1. Администратор открывает карточку клиента.
2. Выбирает добавление оборудования.
3. Указывает тип, производителя, модель и серийный номер.
4. Система проверяет данные.
5. Система сохраняет оборудование и связывает его с клиентом.

**Альтернативный сценарий:** при некорректных данных система выводит сообщение об ошибке.

### UC-3. Создание заказа

**Актор:** Администратор

**Предусловие:** клиент и его оборудование зарегистрированы.

**Основной сценарий:**
1. Администратор открывает карточку оборудования.
2. Создает новый заказ.
3. Указывает описание неисправности.
4. Система присваивает заказу уникальный номер.
5. Система устанавливает начальный статус.
6. Заказ сохраняется.

**Альтернативный сценарий:** если данные об оборудовании отсутствуют, администратор должен сначала зарегистрировать его.

### UC-4. Назначение мастера

**Актор:** Администратор

**Предусловие:** заказ создан, в системе есть зарегистрированные мастера.

**Основной сценарий:**
1. Администратор открывает карточку заказа.
2. Выбирает функцию назначения мастера.
3. Выбирает сотрудника из списка.
4. Подтверждает назначение.
5. Система сохраняет информацию.

**Альтернативный сценарий:** если мастер не выбран, назначение не выполняется.

### UC-5. Проведение диагностики

**Актор:** Мастер

**Предусловие:** мастер авторизован и назначен на заказ.

**Основной сценарий:**
1. Мастер открывает список назначенных заказов.
2. Выбирает нужный заказ.
3. Проводит диагностику.
4. Вносит результаты и предполагаемую стоимость ремонта.
5. Сохраняет информацию.

**Альтернативный сценарий:** если обязательные данные не заполнены, система предлагает дополнить информацию.

### UC-6. Выполнение ремонта

**Актор:** Мастер

**Предусловие:** диагностика завершена, ремонт согласован клиентом.

**Основной сценарий:**
1. Мастер открывает заказ.
2. Начинает ремонт.
3. Фиксирует выполненные работы.
4. Указывает использованные запчасти.
5. Завершает ремонт.
6. Система обновляет статус заказа.

**Альтернативный сценарий:** если необходимых запчастей нет в наличии, ремонт приостанавливается до их поступления.

### UC-7. Учет запчастей

**Актор:** Кладовщик

**Предусловие:** кладовщик авторизован в системе.

**Основной сценарий:**
1. Кладовщик открывает складской модуль.
2. Выбирает операцию поступления или списания.
3. Указывает запчасть и количество.
4. Система проверяет доступность запчастей.
5. Система обновляет складские остатки.

**Альтернативный сценарий:** если количество для списания превышает остаток, система отклоняет операцию.

### UC-8. Просмотр заказов

**Актор:** Руководитель

**Предусловие:** руководитель авторизован в системе.

**Основной сценарий:**
1. Руководитель открывает раздел заказов.
2. Система отображает список всех заказов.
3. Руководитель использует фильтры по статусам.
4. При необходимости открывает карточку заказа.

### UC-9. Формирование отчета

**Актор:** Руководитель

**Предусловие:** руководитель авторизован в системе.

**Основной сценарий:**
1. Руководитель открывает раздел отчетности.
2. Выбирает период.
3. Запрашивает формирование отчета.
4. Система рассчитывает количество заказов и сумму платежей.
5. Отображает результаты.

**Альтернативный сценарий:** если за выбранный период отсутствуют данные, система отображает пустой отчет.

### UC-10. Управление пользователями

**Актор:** Системный администратор

**Предусловие:** системный администратор авторизован в системе.

**Основной сценарий:**
1. Администратор открывает раздел управления пользователями.
2. Создает новую учетную запись или выбирает существующую.
3. Указывает данные пользователя.
4. Назначает роль.
5. Сохраняет изменения.

**Альтернативный сценарий:** если обязательные данные не заполнены, система не сохраняет учетную запись.
